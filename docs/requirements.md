## 1. プロジェクト概要

### 1.1 プロジェクトの目的

日本語学習者向けの学習サイト。日本語圏のVTuberの切り抜き動画を使用した日本語学習コンテンツを提供する。

### 1.2 主要な特徴

- VTuberの切り抜き動画を活用した日本語学習コンテンツ
- メッセージアプリ風のUIで文字起こしを表示
- 日本語・英語・解説の表示をカスタマイズ可能
- 発話者を選択して一人称/三人称UIを切り替え可能
- 静的サイトとして構築（バックエンド不要）

## 2. データ構造

### 2.1 記事データ（JSON形式）

記事データは以下のJSON形式で管理します。

```json
{
  "id": "article-001",
  "title": "VTuberの日常会話",
  "description": "VTuberの日常会話を日本語学習用に解説した記事です。",
  "createdAt": "2024-01-01T00:00:00Z",
  "youtubeVideoId": "dQw4w9WgXcQ",
  "category": "日常会話",
  "tags": ["VTuber", "日常会話", "初級"],
  "speakers": [
    {
      "id": "speaker-001",
      "name": "さくらみこ",
      "icon": "https://example.com/icons/sakuramiko.png"
    }
  ],
  "transcript": [
    {
      "speakerId": "speaker-001",
      "japanese": "今日はいい天気ですね",
      "japaneseWithRuby": "今日<ruby>きょう</ruby>はいい<ruby>天気</ruby><ruby>てんき</ruby>ですね",
      "hiragana": "きょうはいてんきですね",
      "english": "It's nice weather today, isn't it?",
      "explanation": "「いい天気」は「good weather」を意味します。",
      "timestamp": 120
    }
  ]
}
```

### 2.2 フィールド定義

#### 記事レベル

| フィールド | 型 | 必須 | 説明 |
|-----------|-----|------|------|
| `id` | string | ✅ | 記事を一意に識別するID |
| `title` | string | ✅ | 記事のタイトル |
| `description` | string | ✅ | 記事の説明文・要約（記事一覧で表示） |
| `createdAt` | string | ✅ | ISO 8601形式の日時文字列（並び替えに使用） |
| `youtubeVideoId` | string | ✅ | YouTube動画のID |
| `category` | string | ✅ | カテゴリ名 |
| `tags` | string[] | ✅ | タグの配列 |
| `speakers` | Speaker[] | ✅ | 発話者の配列 |
| `transcript` | Transcript[] | ✅ | 文字起こしの配列 |

#### 発話者（Speaker）

| フィールド | 型 | 必須 | 説明 |
|-----------|-----|------|------|
| `id` | string | ✅ | 発話者ID |
| `name` | string | ✅ | 発話者名 |
| `icon` | string | ❌ | アイコン画像のURL（参照できない場合はデフォルトアイコンを使用） |

#### 文字起こし（Transcript）

| フィールド | 型 | 必須 | 説明 |
|-----------|-----|------|------|
| `speakerId` | string | ✅ | 発話者ID（speakers配列内のIDと一致） |
| `japanese` | string | ✅ | 日本語テキスト（漢字のみ） |
| `japaneseWithRuby` | string | ✅ | 漢字+ふりがな形式（デフォルト表示） |
| `hiragana` | string | ✅ | ひらがなテキスト |
| `english` | string | ✅ | 英語翻訳 |
| `explanation` | string | ✅ | 解説テキスト（リンクを含む場合はHTML形式で記述可能） |
| `timestamp` | number | ❌ | 動画内のタイムスタンプ（秒数、将来の同期機能用） |

### 2.3 データ管理

- **保存場所**: `data/articles/`フォルダに各記事をJSONファイルで保存
- **読み込み方法**: Next.jsの`getStaticProps`で読み込み（ビルド時に処理）
- **メタデータ**: ビルド時に`data/articles-index.json`を自動生成（検索用）
  - 含まれるフィールド：`id`, `title`, `description`, `category`, `tags`, `speakers`（名前のみ）, `createdAt`, `youtubeVideoId`

### 2.4 記事管理方法

- 記事の編集はJSONファイルを直接書き換える形式
- 将来的には編集ページを用意し、簡単に記事を作成・編集できるようにする予定

## 3. 機能要件

### 3.1 トップページ（記事一覧）

#### 3.1.1 記事一覧表示

- 記事の一覧を表示する
- 記事をクリックすると記事詳細ページに遷移する
- **表示方法**: ページネーション（ページ分割）を実装
- **並び順**: 作成日時順（新しい順）、並び順の変更機能は不要

#### 3.1.2 記事カードの表示内容

- 記事タイトル
- サムネイル画像（YouTube動画のサムネイルを使用）
- カテゴリ・タグ
- 記事の説明文（要約）

#### 3.1.3 カテゴリ・タグ機能

- 記事にカテゴリとタグを設定できる
- カテゴリやタグで記事を絞り込める
- **カテゴリの管理**: 記事から自動抽出（記事データに含まれるカテゴリを一覧化）
- **カテゴリの階層構造**: 不要（フラット構造）

#### 3.1.4 検索機能

- 記事のタイトルで検索可能
- 記事に登場する発話者の名前で検索可能
- カテゴリやタグで検索・絞り込み可能
- 可能であれば記事の内容（文字起こし、解説など）でも検索可能

**実装方法**: クライアントサイド検索（推奨）
- 記事データをJSONファイルから読み込み、JavaScriptでフィルタリング
- ビルド時に全記事データを読み込んで、クライアント側で検索実行
- 記事数が少ない場合（100件程度まで）に適している

### 3.2 記事詳細ページ

#### 3.2.1 動画埋め込み

- YouTubeに投稿されているVTuberの切り抜き動画を埋め込み表示する
- 動画は記事ごとに設定されたYouTube動画IDを使用する
- YouTube IFrame APIを使用

#### 3.2.2 文字起こし表示（メッセージアプリUI）

**基本仕様**
- メッセージアプリのようなUIで文字起こしを表示する
- 各発話は吹き出し形式で表示される

**発話者機能**
- 発話者ごとにアイコンを表示する
  - アイコン画像が参照できない場合はデフォルトアイコンを表示する
  - デフォルトアイコン：`public/images/default-speaker-icon.svg`（統一デザイン）
- ユーザーが発話者を選択できる（フォーカス発話者）
- 選択された発話者（フォーカス発話者）の吹き出しは一人称UIで表示
- それ以外の発話者の吹き出しは三人称UIで表示
- 同じ発話者によるセリフが連続する場合、2回目以降はアイコンを非表示にする
- **フォーカス発話者の初期値**: その記事における最初の発話者をデフォルト発話者として自動選択

**吹き出しの内容**
- 日本語の文字起こし
- 英語の翻訳
- 解説（文法説明、語彙説明、文化背景など幅広い情報を含む）
  - 形式はテキストのみ
  - リンクは参照可能

**表示設定**
- 設定画面から以下の表示/非表示を切り替え可能：
  - 日本語の表示/非表示
  - 英語の表示/非表示
  - 解説の表示/非表示
- すべて非表示にすることはできない（最低1つは表示必須）
- **表示設定の初期値**: 日本語・英語・解説すべて表示

**日本語表記オプション**
- 日本語の表示形式を選択可能：
  - 漢字表記のみ
  - 漢字 + ふりがな表記（手作業で入力、デフォルト）
  - ひらがな表記のみ
- **ふりがな生成**: 自動生成しない、記事作成者が手作業でJSONファイルに入力する形式

## 4. UI/UX要件

### 4.1 デザイン

- メッセージアプリ風のUIデザイン
- 発話者ごとに異なる吹き出しスタイル（一人称/三人称）
- アイコンの表示/非表示制御
- レスポンシブデザイン対応
  - モバイルデバイス対応
  - タブレット対応

### 4.2 インタラクション

- 発話者の選択機能
- 表示設定の切り替え機能
- 日本語表記形式の切り替え機能

### 4.3 UI配置

**設定画面の配置**
- 記事詳細ページの上部に固定表示
- 常に表示されるため、設定変更が容易
- モバイルでもアクセスしやすい

**発話者選択UI**
- 発話者一覧を上部に表示し、アイコンをクリックで選択
- 視覚的に分かりやすく、直感的な操作が可能
- 発話者のアイコンと名前を同時に表示

### 4.4 ローディング状態

- 記事一覧の読み込み中表示
- 動画の読み込み中表示（YouTube APIの読み込み状態を表示）
- 検索実行中の表示

## 5. 技術要件

- **フレームワーク**: React + Next.js

- バックエンドは不要（静的サイトとして構築）

### 5.3 データ管理

- 記事データはJSONファイルで管理
- 記事の編集はJSONファイルを直接書き換える形式

### 5.4 ユーザー機能

- ユーザー認証機能は不要
- ユーザーごとの設定保存機能は不要（セッション内のみ有効）

- モダンブラウザ（Chrome、Firefox、Safari、Edge）の最新版に対応

## 6. 詳細仕様（確定事項）

### 6.1 エラーハンドリング

- **記事が見つからない場合**: 404ページを実装
- **YouTube動画が読み込めない場合**: エラーメッセージを表示
- **発話者のアイコンが読み込めない場合**: デフォルトアイコンを自動表示
- **JSONファイルの形式が不正な場合**: ビルド時にエラーを検出

### 6.2 タイムスタンプの形式

- **形式**: 秒数（数値型）
- **例**: `"timestamp": 120`（動画の120秒時点）
- **用途**: 将来の動画同期機能で使用予定
- **必須性**: オプショナルフィールド（記事に含めなくても可）

### 6.3 タグ機能の将来拡張

- **タグの自動補完機能**: フェーズ5で実装（検討事項）
- **タグの使用頻度表示**: フェーズ5で実装（検討事項）

## 付録

### カテゴリ階層構造のメリット（参考情報）

カテゴリの階層構造を採用する場合のメリット：

- 大分類から小分類への絞り込みが可能（例：VTuber > ホロライブ > さくらみこ）
- カテゴリの整理がしやすく、大量の記事がある場合に有効
- ナビゲーションの階層化により、ユーザーが目的の記事を見つけやすい
- ただし、記事数が少ない場合はフラット構造の方がシンプルで使いやすい

**決定事項**: 今回はフラット構造を採用
